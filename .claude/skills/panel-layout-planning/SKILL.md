# 패널 레이아웃 설계 스킬

## 언제 사용

- 스토리 씬 비트를 받아 페이지 단위 패널 시퀀스로 변환할 때
- 사용자가 "X 페이지만 다시 짜줘" 요청한 경우
- `story-writer`로부터 "씬 분량 조정"을 위해 페이지 추산이 필요할 때

## 핵심 원칙: 세로 스크롤 페이싱

웹툰은 만화책이 아니다. 좌→우 4컷이 아니라, 위→아래 스크롤 리듬이 본체.

| 의도 | 도구 |
|------|------|
| 침묵·여운 | 큰 여백, 풀-블리드 배경 컷 |
| 충격·반전 | 갑작스러운 풀-페이지 컷 + 이전 작은 컷들의 압축 |
| 시간 압축 | 같은 페이지에 작은 컷 4~6개 |
| 정보 전달 | 미디엄 와이드 + 말풍선 큰 자리 |

**Why this matters:** 패널 크기는 곧 시간이다. 큰 컷에서 독자는 오래 머문다. 감정의 무게와 패널 크기가 일치하지 않으면 페이싱이 깨진다.

## 작업 순서

### 1. 컨텍스트 로딩
- `_workspace/episode-{NN}/01_story.md` — 씬 비트·감정 곡선
- `_workspace/episode-{NN}/02_character_prompts.md` — 씬별 등장 인물
- `_workspace/style-guide.md` — 평균 페이지 수, 페이싱 컨벤션

### 2. 씬당 페이지 추산
- 씬당 1~3 페이지 기본
- 한 씬에 4페이지를 넘어가면 → `story-writer`에게 씬 분할 요청 (사건이 너무 많음)
- 한 씬이 0.5페이지 이하 → `story-writer`에게 씬 통합 또는 사건 추가 요청

### 3. 페이지별 패널 설계
각 페이지마다 패널 2~5개. 패널마다:
- **앵글/사이즈**: [Wide], [Medium], [Close-up], [Full bleed], [Silent]
- **연출 내용**: 누가 무엇을 하는가 (1문장)
- **시선 유도**: 다음 패널로 시선이 흐르는 방향
- **말풍선 자리**: 인물 얼굴·중요 사물을 피한 빈 공간 위치

### 4. 큰 비트 표시
페이싱의 "산"이 되는 컷을 명시:
- 충격 컷 (씬의 절정)
- 다음 화 훅 컷 (마지막 페이지)

이 컷들은 반드시 풀-블리드 또는 페이지 절반 이상 크기.

### 5. 산출

`_workspace/episode-{NN}/03_panel_layout.md`에 저장. 패널 번호는 `{페이지}.{패널}` 형식 — `dialogue-editor`가 1:1 매칭함.

## 하지 말 것

- **모든 패널을 미디엄 샷으로 채우기 금지** → 페이싱이 평탄해짐
- **대사 자리 미지정 금지** → `dialogue-editor`가 인물 얼굴 위에 말풍선을 올리게 만듦
- **스토리 사건 변경 금지** → 페이지 분량 조정 요청만, 사건 자체는 `story-writer`가 결정

## 후속 작업

- 부분 재설계 요청 ("Scene 3만 다시") → 해당 씬에 해당하는 페이지 블록만 재작성, 다른 페이지 번호는 그대로 둠
- 페이지 번호가 변경되면 → `dialogue-editor`에게 매핑 변경 알림 (패널 번호 동기화 필요)
