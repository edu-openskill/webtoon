# 웹툰 스토리 작성 스킬

## 언제 사용

- 신규 에피소드의 씬 단위 스토리 비트를 처음 작성할 때
- 기존 에피소드 스토리에 사용자 피드백을 반영하여 부분 재작성할 때
- 다른 팀원(`dialogue-editor`, `panel-layout-planner`)으로부터 "씬 조정" 요청을 받았을 때

## 작업 순서

### 1. 컨텍스트 로딩
- `_workspace/style-guide.md`를 먼저 읽는다. 없으면 사용자에게 생성을 제안하되, 기본값(웹툰 일반 컨벤션)으로 진행 가능.
- `_workspace/series-bible.md`가 있으면 읽는다 (시리즈 전체 설정·금기·인물).
- 이전 에피소드의 `01_story.md`가 있으면 마지막 화의 "다음 화 훅"을 확인하여 자연스러운 이어짐을 보장.

### 2. 의도 명확화
- 사용자가 제공한 에피소드 의도에서 다음을 추출:
  - **코어 감정 변화**: 시작 감정 → 끝 감정 (예: 안도 → 배신감)
  - **시리즈상 위치**: 도입/전환점/클라이맥스/하강 등
  - **이번 화 후크**: 독자가 다음 화를 기다리게 할 한 가지

의도가 모호하면 단 1회 명확화 질문, 그 후엔 가장 그럴듯한 해석으로 진행하고 가정을 상단에 명시.

### 3. 씬 비트 설계 (8~12씬)
각 씬마다:
- **장소/시간**
- **시작 감정** (등장 인물 기준)
- **사건** (turn — 씬 끝나기 전에 무언가 변해야 함)
- **끝 감정**
- **다음 씬 연결**

**Why this matters:** 씬마다 감정이 변하지 않으면 페이지가 정체된다. 웹툰은 스크롤이 진행감의 본체라서, 사건 없는 씬은 독자 이탈을 부른다.

### 4. 마지막 씬은 훅
마지막 씬은 반드시 **다음 화로 이어지는 질문 또는 미해결 긴장**으로 끝난다. 깔끔한 종결은 시리즈에 독.

### 5. 산출

`_workspace/episode-{NN}/01_story.md`에 저장. 형식은 에이전트 정의의 출력 템플릿을 따른다.

## 하지 말 것

- **패널 분할 지시 금지** ("이 부분 클로즈업으로") → `panel-layout-planner`의 영역
- **대사 본문 작성 금지** → 씬 비트에는 "핵심 대사 의도"만 (예: "A가 B의 거짓말을 추궁한다"), 실제 대사는 `dialogue-editor`가 작성
- **이미지 프롬프트 금지** → `character-prompt-designer`의 영역

## 후속 작업

이미 `01_story.md`가 있을 때:
- 사용자가 "X 씬만 다시" → 해당 씬 블록만 재작성, 다른 씬은 보존
- 다른 에이전트의 피드백 메시지가 있을 때 → 피드백 사항만 수정하고 상단에 changelog 한 줄 추가
